# Architecture

## Optional runtime fleet (0.3.4)

`config/fleet-profile.ini` remains the full development reference. It no longer defines hard player vehicle requirements: the generator emits only damnlib/WayMoreCars requirements and optional ordering edges for vehicle packs. The catalog's `scriptProviders` map and shared `Fleet` module intersect enabled providers with native script availability before constructing candidates. Aliases, profession selectors, regional patrol lists, scene draws and final map balancing use that same boundary. Compatible ordinary styles share available ordinary cars; absent specialist families remain empty. Zero installed KI5 packs explicitly empties managed pools, including the otherwise preserved burnt props.

The importer replaces bundled variant bodies with native empty declarations and retains their attributed bodies in generated `OptionalVehicles.lua`. Models remain in the normal script phase. Before catalog filtering, enabled base providers initialize only their empty variants through native `VehicleScript.Load`/`Loaded`; absent bases keep inert zero-skin/zero-part IDs, excluded from choices. Base-specific MCV Lua extensions guard their native base before loading armor helpers. This avoids missing-template warnings without adding a Java component or dependency. [Optional fleets](optional-fleets.md) records migration behavior, test profiles, provenance and acceptance boundaries. The earlier full-reference generator/data flow below remains applicable, with hard requirements now restricted to the two support modules.

`config/fleet-profile.ini` declares the external full fleet independently of any private server. `config/bundled-sources.json` selects the attributed addon modules. `scripts/import-content.py` reads their immutable Workshop downloads, combines selected common/Build 42 media, namespaces imported Lua files and helper requires, merges MCV names, and omits six reviewed older MCV vehicle definitions. Non-Lua asset paths and upstream sandbox keys remain intact. Every shipped output, original path/hash, version-layer decision and omitted definition is recorded in `docs/imported-content.json`, also shipped under `provenance/`. The importer replaces/removes only its unchanged previously manifested outputs.

`scripts/generate-fleet-catalog.ps1` scans external and integrated source modules, respects that omission manifest, identifies semantic vehicle IDs, excludes disabled-only optional variants, merges distribution facts and generates `OnlyKI5VehicleSpawnLiveryOverhaul_Catalog.lua` plus `ki5-provider-inventory.json`. Versioned modules contribute the selected B42 layer and common/media; root media contributes only for unversioned modules. This prevents B41-only vehicle IDs from entering the current runtime catalog. Current external KI5 definitions win all six overlaps; imported Lua references use the external definitions' canonical spelling. New collisions fail generation. The external profile determines optional load-order edges; only damnlib and WayMoreCars are required. Bundled original IDs are incompatible to prevent duplicate activation.

The Catalog owns vehicle groups, exclusions, rarity and weighted candidate lists. SpawnAliases owns exact replacements (including news vans and trailers); PoliceRegions owns jurisdiction/livery roles. Runtime applies the shared policy late in `OnLoadMapZones` and `OnLoadedMapZones`, after WayMoreCars/VMZ mutation. It wraps audited `addVehicleDebug` inputs and has a final pre-creation guard. SmashedPolice removes bypass aliases. PoliceSpawnRouting corrects coordinate-bearing newly created police vehicles through the same regional authority. PoliceLightbars runs on single-player or server authority, never joined clients. It clears a spawn siren before checking saved decisions, existing lights or station exclusions. Emergency ParkingStall names take precedence over broader square metadata, so policegarage inside TownZone is still station parking. Existing decisions keep their lights without rerolling; players can still operate their own sirens normally after spawning.

`TrafficPolicy` is the shared civilian-option and final pool authority. The catalog generator emits explicit custom/protected/category/fallback tables from `config/civilian-spawn-policy.json`; catalog weights exclude custom choices when their multiplier is zero. Nonzero custom weights are scaled once in final pools and direct alias draws. After the legacy military/region passes, TrafficPolicy clones each pool to detach More Car Features' shared highway aliases, normalizes script keys, scales custom variants, supplies ordinary work-vehicle fallbacks for all-custom pools, checks service roles and caps broad-traffic categories plus independently injected optional limo/Elgin entries. It also resolves every nested profession list through SpawnAliases and the same civilian policy. Fractional profession weights live beside the original arrays; a scoped authority wrapper of the native CheckSwap and OnCreateRegion paths draws from those weights with ZombRandFloat, preserves unique/alternate handling and delegates unmanaged lists to the original functions. This prevents 0.025% weights rounding to zero in short integer slot lists. The pre-creation police guard also clears an out-of-range inherited skin when an already-correct regional script is accepted. Normalization before the legacy pass deliberately preserves shared-table identity because military source budgets depend on it. Authored sandbox settings/translations are appended/merged by the importer with separate source hashes in the attribution manifest. See [selection rules](spawn-policy.md).

Runtime explicitly requires the integrated VMZ distribution and zone-registration modules before registering final selection callbacks. This restores the order formerly supplied by separate mods. VMZ keeps its original sandbox keys, zone data, distributions and four scene recipes. The importer remaps its former library imports to four internal authored modules; no YAPZLib source or runtime requirement remains. No Vanilla's extracted duplicate IDs feed the guarded authored suppression pass. WayMoreCars is a required external mod.

## Native military world support

`SpawnSkins` owns new Humvee livery selection. The existing pre-creation routing callback invokes it after aliases resolve, before requiring a coordinate-bearing police square. Its audited six/eight-skin profiles keep the eight-skin medic/JTF entries at 4%/1%. Selection runs only on spawning authority, persists the zero-based decision in vehicle mod data and returns for already-created vehicles. Unknown layouts and separate SWAT/sheriff/burnt scripts are left alone. See [Humvee livery weights](humvee-liveries.md).

- `WorldSupport` owns server/single-player authority checks, small table/angle operations and filling only empty newly created scene containers through native loot APIs.
- `MilitaryZones` registers vehicle zones through `IsoWorld.registerVehiclesZone`, deduplicates callbacks, respects overriding map cells across all lot directories, and retains skinned civilian variants when clearing military source pools. It chains the existing global `reloadLuaFile`, preserving its return values, to merge edits only into explicitly registered map `objects.lua` files before the native loader consumes them. A weak vehicle set gates military parking angles to newly created authoritative vehicles.
- `RoadScene` adapts the original recipes' operations to native `RandomizedWorldBase` vehicle, trailer, personnel, corpse and object APIs. Weighted selection uses the final fleet distribution and validates scripts/towing parts; cardinal transforms place local recipe coordinates in the world.
- `RoadStories` schedules the four recipes from authoritative `LoadChunk` and `OnTick` callbacks. New story selection is restricted to new chunks and eligible roads, sandbox frequency/day bounds and unoccupied loaded footprints. Native chunk-size/square access avoids treating a Java array as a Lua table. Each anchor square stores a versioned plain-data checkpoint under `OnlyKI5VehicleSpawnLiveryOverhaul_RoadStory`. Pending checkpoints can resume on later loads; completed, blocked, failed or partially started scenes never respawn. Processing rotates across at most four candidates every 30 ticks; unloaded/long-deferred entries leave memory while retaining their saved checkpoint.

These are project modules, not an additional library mod. Native placement and personnel behavior may differ from the former library: the native personnel helper places zombies near vehicles, and native towing owns trailer positioning. RoadScene.enableVehicleLightbar checks actual native lightbar hardware; the importer remaps five inherited unconditional mode writes to this helper. This avoids a server-only mode that native clients discard for vehicles without lightbars. Functional fixtures execute all four imported recipes and production callbacks with native services replaced by spies. `check-native-world-api.ps1` separately verifies 32 installed-build API signatures without creating a world. Native scene, save and multiplayer observations are recorded separately in [native acceptance](native-acceptance.md); construction does not prove towing under player input or natural story frequency. Official API references: [IsoWorld](https://projectzomboid.com/modding/zombie/iso/IsoWorld.html) and [RandomizedWorldBase](https://projectzomboid.com/modding/zombie/randomizedWorld/RandomizedWorldBase.html).

All authored runtime filenames, require paths, globals, generated distribution names and modData keys use `OnlyKI5VehicleSpawnLiveryOverhaul` / `only_ki5_overhaul`. Original `Base.*` vehicle IDs and dependency module names are external contracts and must not be renamed. The mod ID is new: do not run the private predecessor alongside it and do not treat it as an automatic save migration.

The package contains authored Lua, attributed addon Lua/scripts/assets/settings/translations, provenance, descriptors, native-gameplay screenshot branding with a generated title layer, and license/credit text. Imported contributions retain their authors' ownership and are excluded from MIT. Base KI5 vehicle packs, damnlib, WayMoreCars and installed game code stay outside Git. YAPZLib is neither copied nor required; it remains compatible for unrelated mods that need it. `scripts/sync-release-metadata.py` synchronizes Workshop text, shipped credits/license/provenance and dependency documentation. Public source inspection and portable checks do not require a game installation.
